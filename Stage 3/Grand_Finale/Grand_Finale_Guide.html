Overview

The Grand Finale is one build with two milestones. Your team has to design and build a table-top paint plant that doses three base colours into a mixing tank in a fixed order, then make about 3,000 mL of Chocolate that matches the judges' reference colour. The whole sequence must run from one press of a single start switch. This guide takes you from an empty table to the finished batch, in the order you should do things.

Fixed numbers used throughout:

  • Pumps: EARTH 4002 diaphragm pumps, 12 V (9 to 14 V), 3.5 A, rated 5.5 L/min (about 90 mL/s) free flow. In a real line with a flow sensor, valves and 5 mm bore tube, expect much less. The similar Stage 2 pump managed about 2 L/min (about 33 mL/s), so plan on 25 to 40 mL/s at full duty until you measure it. That makes Yellow about 10 s, Green about 30 s and Red about 60 s.
  • Solenoid valves: Uflow, 12 V DC 10 W, normally closed (no power means shut), 1/4" BSP brass body, 0 to 10 bar, with a flow arrow cast on the body.
  • Flow sensors: 3-wire Hall-effect pulse sensors of unknown model, so the pulses per mL (k) must be calibrated from scratch. A typical sensor of this size gives roughly 0.5 to 6 pulses per mL. Treat that only as a sanity check.
  • Tube: clear PU 8 mm OD × 5 mm ID, which holds 19.6 mL per metre. Blue tube 8 × 10 mm, which holds about 50 mL per metre.
  • Power: 12 V 30 A SMPS. Only one pump ever runs at a time, plus at most one valve (about 0.8 A), so the peak load is about 6 A.

Do it in this order: draw the P&ID → mechanical build → leak test with water (no power) → electrical wiring → flash both ESP32s → I/O checks → prime → find each pump's slowest reliable duty → calibrate k for each flow sensor → trim with full test doses → water dry run batch (Milestone 1) → switch to colour → Chocolate batch (Milestone 2). Each step relies on the one before it. Calibrating before the dry run means the dry run passes first time.

P&ID

How the plant works

  • Three identical colour lines. Each runs from the tank's single bottom hole → pump Pn → flow sensor FTn → solenoid valve SVn → common header. The flow sensor sits on the pump's discharge, where the line is full and pressurised, so it does not see air bubbles from the suction side. The solenoid valve sits last, as close to the header as possible, so it cuts the dose off sharply.
  • One common header. All lines join one vertical header: flush water enters at the very top through TE-1, Red joins at TE-1, Yellow at Y-1 and Green at Y-2. At the bottom, TE-2 splits it in two, and each branch has a hand ball valve: BV-M goes up into the middle top hole of the mixing tank and BV-J goes down into the 2 L flush jug.
  • Flush line. T-4 water (bottom hole) → BV-F → P4 → SV4 enters at the start of the header, so flush water sweeps every junction on its way out. The colour valves SV1 to SV3 stay shut during a flush, so no water ever enters a colour line and no colour is ever diluted.
  • Why the colour lines themselves don't need flushing between batches: each one only ever carries its own colour. The only section that sees more than one colour is the header, and that is exactly what the flush cleans.
  • Only 4 solenoid valves, so the outlet is switched by hand. For the batch, BV-M is open and BV-J is shut, and the whole dose sequence runs from one START press. When the batch is done, the controller asks you to shut BV-M and open BV-J. A second START press then runs the flush, which goes only to the jug, as the rules require. The one exception is a short timed water "chase" through BV-M straight after the last colour. It pushes the colour left in the header into the mixing tank so every metered drop reaches the batch. It adds about 1 to 2 % water, which does not visibly change the colour.
  • Interlocks in firmware: a pump can only run when its own solenoid valve is open, and closing a valve stops its pump first. Every solenoid valve closes at power-up because they are normally closed. The firmware cannot see the hand valves, so every message says which way they must be set.
  • Tank holes used: Red, Yellow and Green (1 bottom hole each) = outlet. Flush water tank (top + bottom) = bottom outlet, top hole for filling and venting. Mixing tank (3 top holes) = middle hole for the header inlet, one as an air vent, one spare.

Drawing it on paper

  • Use the same layout as Figure 1: tanks on the left, lines running left to right, the header in the middle, the mixing tank and jug on the right. It fits landscape A4 or A3.
  • Symbols (ISA-5.1): a pump is a circle with a tangent discharge line. A ball valve is a bow-tie with a filled dot. A solenoid valve is a bow-tie with a stem and a square box marked S. A flow transmitter is a circle labelled FT n, joined to an inline box. Tees are dots on the line.
  • Put a flow arrow on every line. Write "PU 8 × 5 mm" on the main lines and "blue 8 × 10 mm" at the pump and sensor stubs. Draw the controller as a dashed box (UC-1), and draw signal lines dashed.
  • Write the tag list beside the drawing. Add four notes: "SV1 to SV4 normally closed", "BV-M open / BV-J shut for batch; reversed for flush", "flush water discharged only to J-1 (except the timed chase)" and "dose order Yellow → Green → Red". Draw each tank hole as a small square on the tank outline, in its real position (top or bottom).
  • Before Milestone 1, walk the table with the paper in hand and tick every tag. The judges check that the drawing matches the build, so if you change a tube route, change the drawing too.

Mechanical build

Build and leak test the whole water side before any electronics are connected. Wear goggles and gloves. Teflon tape goes on every threaded joint, with 4 to 6 wraps clockwise as you look at the thread end.

Layout on the table

  1. Tanks: T-1 Red, T-2 Yellow, T-3 Green and T-4 Water in a row at the back. T-5 Mixing tank at the front with the jug J-1 beside it. Put the supply tanks on the same level as the pumps or slightly higher, so the pumps self-prime easily.
  2. Tank holes: fit a hose connection through every hole. The colour tanks' bottom holes go straight to their pumps. The flush tank's bottom hole goes to BV-F (handle in line with the tube means open). Its top hole stays open as a fill and vent hole. On the mixing tank, the middle top hole takes the header inlet and one other stays open as a vent.
  3. Pumps: screw them down in a row in front of the tanks. The inlet faces the tank. Check the arrows or labels on the pump head: a pump plumbed backwards will not pump.
  4. Flow sensors: right after each colour pump, arrow pointing away from the pump. Mount them level, with the wires on top.
  5. Solenoid valves: after each sensor, body arrow pointing toward the header. These are pilot-type brass valves and only seal in the arrow direction. Mount the coil upright.
  6. Header: join the four lines with TE-1, Y-1, Y-2 and TE-2 as in the P&ID, routed neatly with no sags where air can collect. Measure the header length from TE-1 to the end of the tube inside T-5 and write it down. The water chase time is set from that volume (19.6 mL per metre).
  7. Mixing tank branch: TE-2 → BV-M → up to the middle top hole of T-5. The tube end inside must stay above the liquid (about 4 cm above the 3 L mark), so colour can never siphon back.
  8. Jug branch: TE-2 → BV-J → short tube pointing straight down into J-1, so it drains completely after every run. That keeps calibration doses repeatable. Put BV-M and BV-J where you can reach both handles at once, and label them "M" and "J".
  9. Label every component with its tag (masking tape and a marker). It helps the judges and saves time when debugging.

Leak test (no power)

  • Put 2 to 3 L of water in each supply tank (water, not colour; colour comes in Milestone 2). Open BV-F. The solenoid valves are closed with no power, so water fills each line up to its SV.
  • Wait 5 minutes and check every joint with a dry tissue. Re-tape or re-seat anything that weeps. A drip under a pump is usually a tube not pushed fully over the barb or a missing clamp.
  • Check that no water reaches the header. If it does, a solenoid valve is in backwards. NC valves only hold pressure in their arrow direction.

Before first power-on

  • Meter the SMPS output (about 12.0 to 12.5 V) and its polarity at the PCB terminal.
  • With the SMPS on and no USB connected, both ESP32 power LEDs should light and LED10 (12 V) should be on. No valve should click, because valve pins are LOW at boot.
  • Measure the flow sensor S pin against SGND while nothing flows. It should read 0 V or 3.3 V. If it reads a steady 5 V, tell the technical team before running for long, because ESP32 inputs are 3.3 V parts.
  • Pumps never run dry and never against a closed valve. The firmware enforces this, but do not override it with manual commands.

Flashing

  1. Copy chocolate_plant to the laptop and open the folder in VS Code with the PlatformIO extension (File → Open Folder).
  2. The first build downloads the ESP32 platform (espressif32 6.9.0, Arduino core 2.0.17), so do it on Wi-Fi before the event if you can.
  3. One USB cable does both boards. The port is fixed to /dev/ttyUSB0 in platformio.ini. On Linux, run sudo usermod -aG dialout $USER once and log out and back in. If /dev/ttyUSB0 appears and then vanishes on Ubuntu, run sudo apt remove brltty.
  4. SMPS off. Plug the cable into ESP32 #2 (U7) and run pio run -e sensor -t upload (or env:sensor → Upload in the sidebar). Optional check: pio device monitor should print [U7 sensor]; press Ctrl+C to leave.
  5. Unplug, move the cable to ESP32 #1 (U2) and run pio run -e controller -t upload -t monitor. The monitor should print [U2 controller]. U7 keeps its program and runs from the PCB supply, so the cable stays on U2 from now on.
  6. A plain pio run -t upload (or the sidebar's default Upload) only flashes the controller, so the sensor code cannot land on U2 by mistake.
  7. If the upload stalls at "Connecting…", hold the board's BOOT button until it starts writing.
  8. Type help in the monitor. In PlatformIO's monitor, type the command and press Enter. If the monitor echoes nothing, that is normal.

How a dose works

Every metered dose, whether part of the batch or a test, follows the same profile:

  1. Open the line valve SVn (the hand valves must already point the right way: BV-M for the batch, BV-J for tests). Wait 200 ms so the valve is fully open before the pump pushes.
  2. Fast phase: pump at fast duty (default 100 %) until the metered volume reaches target − band. The band is 10 % of the target, but never less than 20 mL. For Yellow that is 270 mL.
  3. Slow phase: drop to slow duty (default 35 %, set from your own test) for the last 10 %. This is the task sheet's tip, done automatically.
  4. Early stop: cut the pump at target − overrun. The overrun is the volume that still passes the sensor after the stop command (pump spin-down plus link delay). After 150 ms the line valve closes.
  5. Settle and learn: keep counting for about 1 s, report the final metered volume, and update the overrun estimate (the average of the old value and this coast), so each dose gets closer than the last.

Safety stops: no pulses within 4 s of starting (empty tank, air lock or shut ball valve), pulses stopping for 2 s mid-dose, lost data from U7, or any dose over 4 minutes. Each one stops every pump, closes every valve and prints the reason. Pressing START during a run aborts it.

Bench test without water

Where to type: ESP32 #1 (U2, controller). Every command in this section goes into the serial monitor of ESP32 #1, with the USB cable on U2. ESP32 #2 (U7, sensors) only knows show and watch, and answers anything else with "commands: show, watch".

This checks the wiring, both firmwares and every component before any water goes in. The pumps must never run dry, so unplug all four pump leads from the MDD10A M1A/M1B/M2A/M2B terminals first and use the driver's output LEDs or a multimeter instead. The USB cable stays on ESP32 #1 (U2) the whole time.

  1. Power and link. SMPS on, then open the monitor. U2 prints [U2 controller]. Type status: it must say link OK with the ok count rising and bad at 0. link DOWN means U7 is not flashed or not powered, or the UART traces have a fault.
  2. START switch. Hold HS-1 down and type status: it shows start=PRESSED. Let go and type it again: start=up.
  3. Valves. valve 1 1 should give a loud click and light the SV1 LED on the PCB, and valve 1 0 clicks it shut. Repeat for 2, 3 and 4, and check each click comes from the right valve. Don't leave a coil on for more than a minute: dry, it has nothing to cool it.
  4. Drivers and PWM. valve 1 1, then pump 1 30, pump 1 100, pump 1 0. DRV1's channel 1 LED should glow dim, then bright, then go out. With a meter on M1A–M1B you read roughly 3.6 V, then about 12 V. Repeat for lines 2 to 4 (P2 = DRV1 CH2, P3 = DRV2 CH1, P4 = DRV2 CH2). pump 1 50 with SV1 shut must answer ! interlock. Finish with off.
  5. Flow sensors. Type status, then blow gently through FT1 in its arrow direction, then status again: only the first count rises. Repeat for FT2 and FT3. If the wrong count rises, two sensor plugs are swapped. If none rise, check S/V/G (V must read 5 V to G).
  6. Dose logic. Give line 2 a fake calibration and a small target, without saving: set k2 1 (1 pulse = 1 mL), then dose 2 60, and blow steadily through FT2 within 4 s. SV2 clicks open, the DRV1 CH2 LED goes bright, then dim at 40 "mL" (target minus the 20 mL slow band), then everything stops and the dose prints a report. Stop blowing during a dose and it must fault with flow stopped after 2 s.
  7. Whole batch sequence. set k1 1, set k2 1, set k3 1, set tgt1 60, set tgt2 30, set tgt3 40. Press START and blow through FT2, then FT3, then FT1 as each line opens (Yellow → Green → Red). The chase runs P4 on its own, with no sensor, and the controller then waits. Press START again to see the flush run P4 for 6 s.
  8. Restore the real settings. Type load, or press EN on U2. Never type save during this test, or the fake k and targets become permanent. Turn the SMPS off and reconnect the pump leads.

If every step passes, the only things left unproven are the plumbing and the real k values, and Commissioning finds those with water.

Commissioning and calibration

Where to type: ESP32 #1 (U2, controller). Every command in this section goes into the serial monitor of ESP32 #1, with the USB cable on U2. ESP32 #2 (U7, sensors) only knows show and watch, and answers anything else with "commands: show, watch".

All of this runs with water in all four supply tanks, the mixing tank empty, the jug empty and on the scale. A gram of water is a millilitre, so the scale is your reference. Put the jug on the scale and tare it before every weighing.

For every step in this section, set the hand valves to the jug: BV-M shut, BV-J open. BV-F (flush tank outlet) stays open.

Step 1: I/O check

  1. On ESP32 #1, type status. It should say link OK with the ok count rising and bad near 0. If the link is down, check that U7 is flashed and powered.
  2. Press START with no pumps armed: status shows start=PRESSED while you hold it. (With calibration missing, a press just prints "not calibrated, batch refused", which is fine.)
  3. Valve click test: valve 1 1 then valve 1 0, and the same for 2 to 4. Each should click. Note any valve that clicks for the wrong number and swap its connector.

Step 2: Prime every line

  • prime 2 5, prime 3 5, prime 1 5 and prime 4 5. Each opens its SV and runs its pump into the jug. Repeat until water flows into the jug steadily with no bubbles in the clear tube.
  • No flow after 4 s gives a "no flow after start" fault. That means a ball valve is shut, the pump is reversed (swap motor leads), the pump is plumbed backwards, or there is an air lock (lift the tube to let air out).
  • Check that FTn's count rises only when line n runs. If FT2 counts while line 1 runs, two sensor connectors are swapped.
  • Empty the jug and type jug 0.

Step 3: Find the slow duty for each pump

The slow phase only helps if the pump still moves water reliably. For each line n:

  1. calrun n 5 30 (5 s at 30 %). If the report shows 0 pulses or a fault, the pump stalled at 30 %. Try 40 %, 50 % and so on.
  2. Take the lowest duty that gives steady pulses, add 10 percentage points for margin, and set it: set slow n … (for example set slow2 40).
  3. Write down the Hz printed at fast duty and at slow duty. Hz × 1000 ÷ k gives mL/s once k is known.

Step 4: Calibrate k (pulses per mL)

Do this for each colour line n = 1, 2, 3:

  1. Empty the jug, put it on the scale and tare.
  2. calrun n 15 (15 s at fast duty). The controller prints the pulse count.
  3. Weigh the jug in grams (= mL), then type k n <grams>.
  4. Repeat 3 times and fill in the table. If the three k values agree within about 2 %, set the average with set k n …. If one is far off, the jug probably overflowed or the tube was not full; redo it.
  5. Type save.

What to expect: the pulses per mL are roughly constant, typically 0.5 to 6. At low flow, turbine sensors often read a little low. That is why step 5 trims k using the real fast-then-slow dose profile instead of trusting the 15 s run alone.

Step 5: Trim with real doses

Now test exactly what the batch will do, but into the jug:

  1. Empty and tare the jug. dose 2 300. Read the report line (metered mL and coast), then weigh.
  2. If the weighed volume differs from 300 by more than 1 % (3 mL), type k 2 <weighed>. That recalculates k from this dose's pulses. Repeat the dose until two in a row land within ±1 %.
  3. Do the same with dose 3 900 and dose 1 900. Red's 1,800 mL fills the 2 L jug almost to the brim, so trim Red with 900 mL doses, or do a final dose 1 1800 mix and weigh the mixing tank if your scale can take it.

Background: the ideas behind this guide

1. Why the doses must be exact

Mixing paint is subtractive: every pigment absorbs part of the light, so each addition makes the mix darker. Pigment can be added but never removed, so an overshoot means a rejected batch. Yellow is only 10 % of the recipe, so an error in Yellow shifts the colour most. If Yellow lands 15 mL high (5 % of its dose), Yellow becomes 10.5 % of the batch, which is a visible hue shift. The same 15 mL on Red is under 1 %. That is why Yellow gets the gentlest treatment: dosed first, with a long slow band compared with its size.

2. Flow sensors and k

A Hall-effect flow sensor has a small turbine. Each time a magnet on the rotor passes the Hall chip, the output pin is pulled low, which gives one pulse. The number of pulses is proportional to the volume that has passed:

V (mL) = N (pulses) ÷ k (pulses per mL)
Q (mL/s) = f (Hz) ÷ k

k depends on the sensor's internal geometry and a little on the flow rate and the liquid's viscosity. That is why you calibrate against a scale (1 g of water = 1 mL), and trim using the same fast-then-slow profile the batch uses. Counting is done on a separate ESP32 with interrupts, so no pulse is missed while the controller is busy.

3. Why slow down near the target

After the controller decides to stop, some liquid still passes. Sensor data is up to 10 ms old, the loop reacts within a few ms, the pump takes tens of ms to spin down, and the line valve closes 150 ms later. The volume that slips through is roughly flow × reaction time:

overshoot ≈ Q × treact
at full speed: 35 mL/s × 0.1 s ≈ 3.5 mL (1.2 % of Yellow)
at slow duty: 8 mL/s × 0.1 s ≈ 0.8 mL (0.3 % of Yellow)

Slowing for the last 10 % cuts the uncertainty several times over, and the learned overrun removes most of what is left. The controller stops early by the amount it has learned usually arrives late.

4. Dead volume in the header

The 5 mm bore tube holds π × (2.5 mm)² × 1000 mm = 19.6 mL per metre. Anything sitting in the shared header after a dose was metered but has not reached the tank. Two features handle it. First, the next colour pushes the previous colour's leftover into the tank. Second, after the last colour, the timed water chase pushes Red's leftover in. The cost is the header's worth of water from the previous flush (pushed in by Yellow) plus the chase water. That is about 1 to 2 % of the batch, which dilutes all three colours equally and does not change the ratios.

5. Normally closed valves and interlocks

A normally closed solenoid valve is shut until its coil is powered. On power loss, an ESP32 reset or a firmware crash, every line closes by itself and nothing siphons into the batch. These Uflow valves are pilot-operated and only seal in their arrow direction, which is why the arrow must point toward the header. The firmware adds interlocks on top. A pump never starts unless its path is open, closing a valve first stops the pump feeding it. The two hand valves are the one thing it cannot check, so its messages always say how they must be set. That protects the diaphragm pumps, which would otherwise build up to their 120 psi cutoff against a closed valve.

6. PWM speed control

The MDD10A switches the 12 V supply to the pump on and off 20,000 times a second. The fraction of time it is on (the duty) sets the average voltage and so the pump speed. Below a certain duty the motor cannot overcome the diaphragm's friction and stalls, which is why step 3 finds the lowest reliable duty before it is used for the slow phase. DIR is tied low on the PCB, so each pump only turns one way.

// Shared definitions for the UART link between ESP32 #2 (sensor, U7) and ESP32 #1 (controller, U2).
//
// U7 sends one line every LINK_PERIOD_MS:
//     F,<seq>,<count1>,<count2>,<count3>*<xx>\n
// count1..3 are the running pulse totals of FS1..FS3 since U7 booted (uint32, they never reset).
// <xx> is the XOR of every character between 'F' and '*' inclusive of 'F', as two hex digits.
// U2 keeps its own baseline, so a lost frame never loses pulses: the next frame carries the total.
#pragma once
#include <Arduino.h>

static const uint32_t LINK_BAUD      = 115200;
static const uint8_t  LINK_RX_PIN    = 16;   // both boards: RX on G16
static const uint8_t  LINK_TX_PIN    = 17;   // both boards: TX on G17
static const uint32_t LINK_PERIOD_MS = 10;   // 100 frames per second

inline uint8_t linkChecksum(const char *s, size_t n) {
  uint8_t x = 0;
  for (size_t i = 0; i < n; i++) x ^= (uint8_t)s[i];
  return x;
}

// ESP32 #2 (U7) · sensor board
// Counts pulses from flow sensors FS1..FS3 and streams the running totals to ESP32 #1 over UART.
// It never drives anything, so it is safe to leave running all the time.
//
// USB serial commands (115200):
//   show      print the three running totals once
//   watch     toggle a 2 Hz print of totals and pulse rates (handy when wiring/priming)

#include <Arduino.h>
#include "link.h"

// PCB sheet 3: FLOW_SENSOR1..3 signal pins on ESP32 #2. (FS4 = G14, FS5 = G27 are unused.)
static const uint8_t FS_PIN[3] = {33, 25, 26};

static volatile uint32_t pulses[3] = {0, 0, 0};
static volatile uint32_t lastEdgeUs[3] = {0, 0, 0};
// Ignore edges closer than this (contact bounce / noise). 300 us = 3.3 kHz, far above any real flow.
static const uint32_t MIN_EDGE_US = 300;

static void IRAM_ATTR countEdge(uint8_t i) {
  uint32_t now = micros();
  if (now - lastEdgeUs[i] >= MIN_EDGE_US) {
    pulses[i]++;
    lastEdgeUs[i] = now;
  }
}
static void IRAM_ATTR isr0() { countEdge(0); }
static void IRAM_ATTR isr1() { countEdge(1); }
static void IRAM_ATTR isr2() { countEdge(2); }

static portMUX_TYPE mux = portMUX_INITIALIZER_UNLOCKED;
static void snapshot(uint32_t out[3]) {
  portENTER_CRITICAL(&mux);
  for (int i = 0; i < 3; i++) out[i] = pulses[i];
  portEXIT_CRITICAL(&mux);
}

static uint32_t seq = 0;
static bool watch = false;

void setup() {
  Serial.begin(115200);
  Serial2.begin(LINK_BAUD, SERIAL_8N1, LINK_RX_PIN, LINK_TX_PIN);
  for (int i = 0; i < 3; i++) pinMode(FS_PIN[i], INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(FS_PIN[0]), isr0, FALLING);
  attachInterrupt(digitalPinToInterrupt(FS_PIN[1]), isr1, FALLING);
  attachInterrupt(digitalPinToInterrupt(FS_PIN[2]), isr2, FALLING);
  Serial.println(F("\n[U7 sensor] FS1=G33 FS2=G25 FS3=G26 -> UART G17 @115200. Commands: show, watch"));
}

void loop() {
  static uint32_t nextFrame = 0, nextWatch = 0;
  static uint32_t prevWatch[3] = {0, 0, 0};
  uint32_t now = millis();

  if ((int32_t)(now - nextFrame) >= 0) {
    nextFrame = now + LINK_PERIOD_MS;
    uint32_t c[3];
    snapshot(c);
    char buf[64];
    int n = snprintf(buf, sizeof(buf), "F,%lu,%lu,%lu,%lu*", (unsigned long)seq++,
                     (unsigned long)c[0], (unsigned long)c[1], (unsigned long)c[2]);
    uint8_t x = linkChecksum(buf, n);
    snprintf(buf + n, sizeof(buf) - n, "%02X\n", x);
    Serial2.print(buf);
  }

  if (watch && (int32_t)(now - nextWatch) >= 0) {
    nextWatch = now + 500;
    uint32_t c[3];
    snapshot(c);
    Serial.printf("FS1 %lu (%lu Hz)  FS2 %lu (%lu Hz)  FS3 %lu (%lu Hz)\n",
                  (unsigned long)c[0], (unsigned long)((c[0] - prevWatch[0]) * 2),
                  (unsigned long)c[1], (unsigned long)((c[1] - prevWatch[1]) * 2),
                  (unsigned long)c[2], (unsigned long)((c[2] - prevWatch[2]) * 2));
    for (int i = 0; i < 3; i++) prevWatch[i] = c[i];
  }

  if (Serial.available()) {
    String cmd = Serial.readStringUntil('\n');
    cmd.trim();
    if (cmd == "show") {
      uint32_t c[3];
      snapshot(c);
      Serial.printf("FS1 %lu  FS2 %lu  FS3 %lu\n", (unsigned long)c[0], (unsigned long)c[1], (unsigned long)c[2]);
    } else if (cmd == "watch") {
      watch = !watch;
      Serial.printf("watch %s\n", watch ? "on" : "off");
    } else if (cmd.length()) {
      Serial.println(F("commands: show, watch"));
    }
  }
}

  for (int p = 0; p < 4; p++) writePump(p, 0);

    Serial.printf("! interlock: P%d needs SV%d open\n", p + 1, p + 1);

  return true;
}

    writePump(v, 0);
    delay(100);

  return true;

  prevCount = p; prevMs = now;
  // CSV: D,t_ms,line,phase,duty%,pulses,mL,mL_per_s
  Serial.printf("D,%lu,%d,%s,%u,%lu,%.1f,%.1f\n", (unsigned long)(now - dose.t0), dose.line + 1, PHASE_NAME[dose.ph],
                pumpPct[dose.line], (unsigned long)p, mlOf(dose.line, p), rate);
}

static void doseStep() {
  if (dose.ph == D_IDLE || dose.ph == D_DONE || dose.ph == D_FAULT) return;
  uint32_t now = millis();
  LineCfg &L = cfg.line[dose.line];
  uint32_t c = counts[dose.line];
  if (c != dose.lastCount) { dose.lastCount = c; dose.lastPulseMs = now; }
  uint32_t p = dosePulses();
  float ml = mlOf(dose.line, p);

  if (dose.ph <= D_SLOW && !linkOk()) { doseFault("lost sensor link"); return; }
  if (now - dose.t0 > MAX_DOSE_MS) { doseFault("dose took too long"); return; }
  if (dose.ph == D_FAST || dose.ph == D_SLOW) {
    uint32_t limit = (p == 0) ? START_STALL_MS : STALL_MS;
    if (now - dose.lastPulseMs > limit) { doseFault(p == 0 ? "no flow after start (empty tank, air, valve shut?)" : "flow stopped (tank empty or pump stalled)"); return; }
  }
  doseTelemetry(now);

  float band = max(dose.target * cfg.bandPct / 100.0f, cfg.bandMinMl);
  float stopAt = dose.target - L.overrun;

  switch (dose.ph) {
    case D_OPEN:
      if (now - dose.tPh >= VALVE_MS) {
        uint8_t d = dose.timed ? dose.duty : L.fast;
        if (!dose.timed && ml >= dose.target - band) d = L.slow;  // tiny dose: go straight to slow
        if (!setPump(dose.line, d)) { doseFault("interlock refused pump start"); return; }
        dose.ph = (d == L.slow && !dose.timed) ? D_SLOW : D_FAST;
        dose.tPh = now; dose.lastPulseMs = now;
      }
      break;
    case D_FAST:
      if (dose.timed) {
        if (now - dose.tPh >= dose.runMs) goto stop;
      } else if (ml >= stopAt) {
        goto stop;
      } else if (ml >= dose.target - band) {
        writePump(dose.line, L.slow);
        dose.ph = D_SLOW; dose.tPh = now;
      }
      break;
    case D_SLOW:
      if (ml >= stopAt) goto stop;
      break;
    case D_STOP:
      if (now - dose.tPh >= STOP_TO_CLOSE_MS) {
        setValve(dose.line, false);
        dose.ph = D_SETTLE; dose.tPh = now;
      }
      break;
    case D_SETTLE:
      if (now - dose.tPh >= SETTLE_MS && now - dose.lastPulseMs >= 300) {
        dose.pulsesFinal = p;
        dose.mlFinal = ml;
        lastPulses[dose.line] = p;
        if (dose.timed) {
          Serial.printf("= calrun %s: %lu pulses in %lu ms (%.1f Hz). Now weigh the jug and type: k %d <mL>\n",
                        LINE_NAME[dose.line], (unsigned long)p, (unsigned long)dose.runMs,
                        p * 1000.0f / dose.runMs, dose.line + 1);
        } else {
          float coast = dose.mlFinal - dose.mlAtStop;
          if (cfg.learn && coast >= 0 && coast < 50) L.overrun = 0.5f * L.overrun + 0.5f * coast;
          Serial.printf("= %s target %.1f mL, metered %.1f mL (error %+.1f mL, %+.2f %%), coast %.1f mL, next overrun %.1f mL, pulses %lu\n",
                        LINE_NAME[dose.line], dose.target, dose.mlFinal, dose.mlFinal - dose.target,
                        (dose.mlFinal - dose.target) * 100.0f / dose.target, coast, L.overrun, (unsigned long)p);
        }
        dose.ph = D_DONE;
      }
      break;
    default:
      break;
  }
  return;
stop:
  writePump(dose.line, 0);
  dose.mlAtStop = ml;
  dose.stopCount = c;
  dose.ph = D_STOP; dose.tPh = now;
}

// ---------------------------------------------------------------- simple timed flush-pump runs
struct Timed { bool on = false; uint32_t t0 = 0, ms = 0; int phase = 0; bool toMix = false; } p4run;
static float jugMl = 0;  // estimated water in the jug since it was last emptied

static bool p4Begin(bool toMix, uint32_t ms) {
  if (!toMix && jugMl + cfg.p4Rate * ms / 1000.0f > 1800.0f) {
    Serial.printf("! jug would overflow (now ~%.0f mL). Empty it, type 'jug 0', then 'flush'.\n", jugMl);
    return false;
  }
  setValve(SV_FLUSH, true);
  p4run = Timed();
  p4run.on = true; p4run.t0 = millis(); p4run.ms = ms; p4run.toMix = toMix;
  Serial.printf("> P4 water %lu ms, %s (%s)\n", (unsigned long)ms, toMix ? "chase" : "flush", toMix ? NEED_MIX : NEED_JUG);
  return true;
}
static void p4Step() {
  if (!p4run.on) return;
  uint32_t now = millis();
  switch (p4run.phase) {
    case 0:
      if (now - p4run.t0 >= VALVE_MS) {
        if (!setPump(3, cfg.p4)) { allOff(); p4run.on = false; return; }
        p4run.phase = 1; p4run.t0 = now;
      }
      break;
    case 1:
      if (now - p4run.t0 >= p4run.ms) { writePump(3, 0); p4run.phase = 2; p4run.t0 = now; }
      break;
    case 2:
      if (now - p4run.t0 >= STOP_TO_CLOSE_MS) {
        setValve(SV_FLUSH, false);
        if (!p4run.toMix) jugMl += cfg.p4Rate * p4run.ms / 1000.0f;
        p4run.on = false;
        Serial.printf("= P4 done. Jug estimate ~%.0f mL\n", jugMl);
      }
      break;
  }
}

// ---------------------------------------------------------------- batch sequence
enum Batch { B_IDLE, B_LINE, B_CHASE, B_WAIT_FLUSH, B_FLUSH, B_DONE, B_ABORTED };
static Batch batch = B_IDLE;
static int batchIdx = 0;
static float result[3];
static uint32_t batchT0 = 0;

static bool busy() { return batch == B_LINE || batch == B_CHASE || batch == B_FLUSH || p4run.on ||
                            (dose.ph != D_IDLE && dose.ph != D_DONE && dose.ph != D_FAULT); }

static void batchAbort(const char *why) {
  allOff();
  p4run.on = false;
  if (dose.ph != D_DONE && dose.ph != D_IDLE) dose.ph = D_FAULT;
  batch = B_ABORTED;
  Serial.printf("! BATCH ABORTED: %s\n", why);
}

static void batchStart() {
  if (busy()) { Serial.println(F("! busy")); return; }
  for (int i = 0; i < 3; i++)
    if (cfg.line[i].k <= 0) { Serial.printf("! %s not calibrated, batch refused\n", LINE_NAME[i]); return; }
  if (!linkOk()) { Serial.println(F("! no data from sensor board U7, batch refused")); return; }
  allOff();
  Serial.printf("\n>>> BATCH START (BV-M open, BV-J shut)  order %s -> %s -> %s, then chase %lu ms, flush %lu ms\n",
                LINE_NAME[cfg.order[0]], LINE_NAME[cfg.order[1]], LINE_NAME[cfg.order[2]],
                (unsigned long)cfg.chaseMs, (unsigned long)cfg.flushMs);
  batchT0 = millis();
  batchIdx = 0;
  int l = cfg.order[0];
  if (!doseBegin(l, cfg.line[l].target, true, false, 0, 0)) { batchAbort("first dose would not start"); return; }
  batch = B_LINE;
}

static void batchReport() {
  Serial.println(F("\n===== BATCH REPORT ====="));
  float tot = 0;
  for (int i = 0; i < 3; i++) {
    int l = cfg.order[i];
    tot += result[l];
    Serial.printf("%-7s target %7.1f mL  metered %7.1f mL  error %+6.1f mL (%+.2f %%)\n", LINE_NAME[l],
                  cfg.line[l].target, result[l], result[l] - cfg.line[l].target,
                  (result[l] - cfg.line[l].target) * 100.0f / cfg.line[l].target);
  }
  Serial.printf("colour total %.1f mL, + chase water ~%.0f mL, time %.1f s\n", tot,
                cfg.p4Rate * cfg.chaseMs / 1000.0f, (millis() - batchT0) / 1000.0f);
  for (int i = 0; i < 3; i++) {
    int l = cfg.order[i];
    Serial.printf("ratio %s %.1f %%  ", LINE_NAME[l], tot > 0 ? result[l] * 100.0f / tot : 0);
  }
  Serial.println(F("\n========================"));
}

static void batchStep() {
  switch (batch) {
    case B_LINE:
      if (dose.ph == D_FAULT) { batchAbort(dose.fault); break; }
      if (dose.ph == D_DONE) {
        result[dose.line] = dose.mlFinal;
        if (++batchIdx < 3) {
          int l = cfg.order[batchIdx];
          if (!doseBegin(l, cfg.line[l].target, true, false, 0, 0)) batchAbort("next dose would not start");
        } else {
          // BV-M is still open: push the last colour out of the header into the mixing tank
          if (cfg.chaseMs == 0) batch = B_CHASE;
          else if (p4Begin(true, cfg.chaseMs)) batch = B_CHASE;
          else batchAbort("chase would not start");
        }
      }
      break;
    case B_CHASE:
      if (!p4run.on) {
        batchReport();
        batch = B_WAIT_FLUSH;
        Serial.println(F(">>> BATCH COMPLETE. To flush: SHUT BV-M, OPEN BV-J, then press START (or type flush)."));
      }
      break;
    case B_FLUSH:
      if (!p4run.on) {
        batch = B_DONE;
        Serial.println(F(">>> FLUSH DONE. Before the next batch: SHUT BV-J, OPEN BV-M. Empty the jug when near 2 L."));
      }
      break;
    default:
      break;
  }
}

static void batchFlush() {
  if (busy()) { Serial.println(F("! busy")); return; }
  if (cfg.flushMs == 0 || !p4Begin(false, cfg.flushMs)) { Serial.println(F("! flush not started")); return; }
  batch = B_FLUSH;
}

// ---------------------------------------------------------------- start switch
static void pollStart() {
  static bool last = true, stable = true;
  static uint32_t tChange = 0;
  bool r = digitalRead(START_PIN);
  if (r != last) { last = r; tChange = millis(); }
  if (millis() - tChange > 40 && r != stable) {
    stable = r;
    if (!stable) {  // pressed (pulled to SGND)
      if (busy()) batchAbort("START pressed during run (used as stop)");
      else if (batch == B_WAIT_FLUSH) batchFlush();
      else batchStart();
    }
  }
}

// ---------------------------------------------------------------- serial commands
static void printConfig() {
  Serial.println(F("line    k(p/mL)  target  fast%  slow%  overrun"));
  for (int i = 0; i < 3; i++)
    Serial.printf("%d %-6s %7.3f %7.1f %5u %6u %8.1f\n", i + 1, LINE_NAME[i], cfg.line[i].k, cfg.line[i].target,
                  cfg.line[i].fast, cfg.line[i].slow, cfg.line[i].overrun);
  Serial.printf("order %d%d%d  band %.1f %% (min %.0f mL)  learn %d\n", cfg.order[0] + 1, cfg.order[1] + 1, cfg.order[2] + 1,
                cfg.bandPct, cfg.bandMinMl, cfg.learn);
  Serial.printf("p4 %u %%  p4rate %.1f mL/s  chase %lu ms  flush %lu ms  jug ~%.0f mL\n", cfg.p4, cfg.p4Rate,
                (unsigned long)cfg.chaseMs, (unsigned long)cfg.flushMs, jugMl);
}
static void printStatus() {
  Serial.printf("link %s (ok %lu, bad %lu)  counts %lu %lu %lu  start=%s\n", linkOk() ? "OK" : "DOWN",
                (unsigned long)framesOk, (unsigned long)framesBad, (unsigned long)counts[0], (unsigned long)counts[1],
                (unsigned long)counts[2], digitalRead(START_PIN) ? "up" : "PRESSED");
  Serial.print(F("valves "));
  for (int v = 0; v < 4; v++) Serial.printf("SV%d=%d ", v + 1, valveOpen[v]);
  Serial.print(F(" pumps "));
  for (int p = 0; p < 4; p++) Serial.printf("P%d=%u%% ", p + 1, pumpPct[p]);
  static const char *BN[] = {"idle", "dosing", "chase", "WAITING FOR FLUSH (shut BV-M, open BV-J, press START)", "flush", "done", "aborted"};
  Serial.printf("\nbatch %s  dose %s\n", BN[batch], PHASE_NAME[dose.ph]);
}
static void help() {
  Serial.println(F(
      "--- Team 13 Chocolate controller (line 1=RED 2=YELLOW 3=GREEN 4=FLUSH) ---\n"
      "start | abort          run / stop the full batch (same as the START switch)\n"
      "                       after a batch, the next START press runs the flush\n"
      "  hand valves: batch/chase = BV-M open, BV-J shut; everything else = BV-M shut, BV-J open\n"
      "status | show          live I/O state | settings\n"
      "prime <1-4> <sec>      run a line into the JUG at fast duty (fill lines, purge air)\n"
      "calrun <1-3> <sec> [%] timed run into the JUG, counts pulses (calibration)\n"
      "k <1-3> <mL>           set k = pulses of last calrun/dose / mL weighed\n"
      "dose <1-3> <mL> [mix]  metered dose with full fast/slow profile (default to JUG)\n"
      "chase | flush          water into mixing tank | water flush to jug\n"
      "jug <mL>               set jug estimate (jug 0 after emptying)\n"
      "valve <1-4> <0|1>      manual valve, idle only\n"
      "pump <1-4> <%>         manual pump, idle only, interlocked\n"
      "off                    everything off\n"
      "set <key> <value>      keys: k1..3 tgt1..3 fast1..3 slow1..3 ovr1..3 order(e.g. 231)\n"
      "                       band bandmin p4 p4rate chase flush learn\n"
      "save | load | defaults settings in flash"));
}

static void handleCommand(String line) {
  line.trim();
  if (!line.length()) return;
  char buf[96];
  line.toCharArray(buf, sizeof(buf));
  char *cmd = strtok(buf, " ");
  char *a1 = strtok(nullptr, " ");
  char *a2 = strtok(nullptr, " ");
  char *a3 = strtok(nullptr, " ");
  String c(cmd);
  c.toLowerCase();
  int n = a1 ? atoi(a1) : 0;

  if (c == "help" || c == "?") help();
  else if (c == "status") printStatus();
  else if (c == "show") printConfig();
  else if (c == "start") { if (batch == B_WAIT_FLUSH) batchFlush(); else batchStart(); }
  else if (c == "abort" || c == "stop") batchAbort("abort command");
  else if (c == "off") { allOff(); p4run.on = false; dose.ph = D_IDLE; batch = B_IDLE; Serial.println(F("all off")); }
  else if (busy()) Serial.println(F("! busy, type abort first"));
  else if (c == "prime" && n >= 1 && n <= 4 && a2) {
    uint32_t ms = (uint32_t)(atof(a2) * 1000);
    if (n == 4) p4Begin(false, ms);
    else doseBegin(n - 1, 0, false, true, ms, cfg.line[n - 1].fast);
  } else if (c == "calrun" && n >= 1 && n <= 3 && a2) {
    uint8_t duty = a3 ? atoi(a3) : cfg.line[n - 1].fast;
    doseBegin(n - 1, 0, false, true, (uint32_t)(atof(a2) * 1000), duty);
  } else if (c == "k" && n >= 1 && n <= 3 && a2) {
    float ml = atof(a2);
    if (ml <= 0 || lastPulses[n - 1] == 0) Serial.println(F("! need a calrun or dose on that line first, and mL > 0"));
    else {
      cfg.line[n - 1].k = lastPulses[n - 1] / ml;
      Serial.printf("k%d = %lu / %.1f = %.4f pulses/mL (type save to keep)\n", n, (unsigned long)lastPulses[n - 1], ml, cfg.line[n - 1].k);
    }
  } else if (c == "dose" && n >= 1 && n <= 3 && a2) {
    bool mix = a3 && String(a3) == "mix";
    doseBegin(n - 1, atof(a2), mix, false, 0, 0);
  } else if (c == "chase") p4Begin(true, cfg.chaseMs);
  else if (c == "flush") { if (batch == B_WAIT_FLUSH) batchFlush(); else p4Begin(false, cfg.flushMs); }
  else if (c == "jug" && a1) { jugMl = atof(a1); Serial.printf("jug ~%.0f mL\n", jugMl); }
  else if (c == "valve" && n >= 1 && n <= 4 && a2) { setValve(n - 1, atoi(a2)); printStatus(); }
  else if (c == "pump" && n >= 1 && n <= 4 && a2) { setPump(n - 1, atoi(a2)); printStatus(); }
  else if (c == "save") saveConfig();
  else if (c == "load") { loadConfig(); printConfig(); }
  else if (c == "defaults") { setDefaults(); printConfig(); Serial.println(F("(not saved yet)")); }
  else if (c == "set" && a1 && a2) {
    String k(a1);
    k.toLowerCase();
    float v = atof(a2);
    int i = k.length() > 0 ? k.charAt(k.length() - 1) - '1' : -1;
    String base = k.substring(0, k.length() - 1);
    bool ok = true;
    if (i >= 0 && i < 3 && base == "k") cfg.line[i].k = v;
    else if (i >= 0 && i < 3 && base == "tgt") cfg.line[i].target = v;
    else if (i >= 0 && i < 3 && base == "fast") cfg.line[i].fast = constrain((int)v, 0, 100);
    else if (i >= 0 && i < 3 && base == "slow") cfg.line[i].slow = constrain((int)v, 0, 100);
    else if (i >= 0 && i < 3 && base == "ovr") cfg.line[i].overrun = v;
    else if (k == "order" && strlen(a2) == 3) {
      uint8_t o[3]; bool seen[3] = {false, false, false};
      for (int j = 0; j < 3; j++) { o[j] = a2[j] - '1'; if (o[j] > 2 || seen[o[j]]) ok = false; else seen[o[j]] = true; }
      if (ok) memcpy(cfg.order, o, 3);
    } else if (k == "band") cfg.bandPct = v;
    else if (k == "bandmin") cfg.bandMinMl = v;
    else if (k == "p4") cfg.p4 = constrain((int)v, 0, 100);
    else if (k == "p4rate") cfg.p4Rate = v;
    else if (k == "chase") cfg.chaseMs = (uint32_t)v;
    else if (k == "flush") cfg.flushMs = (uint32_t)v;
    else if (k == "learn") cfg.learn = v != 0;
    else ok = false;
    if (ok) { printConfig(); Serial.println(F("(type save to keep)")); }
    else Serial.println(F("! unknown key or bad value"));
  } else Serial.println(F("? type help"));
}

// ---------------------------------------------------------------- setup / loop
void setup() {
  // Valves first: NC valves stay shut while the board boots.
  for (int v = 0; v < 4; v++) { pinMode(SV_PIN[v], OUTPUT); digitalWrite(SV_PIN[v], LOW); }
  for (int p = 0; p < 4; p++) { ledcSetup(p, PWM_FREQ, PWM_BITS); ledcAttachPin(PWM_PIN[p], p); ledcWrite(p, 0); }
  pinMode(START_PIN, INPUT_PULLUP);
  Serial.begin(115200);
  Serial2.begin(LINK_BAUD, SERIAL_8N1, LINK_RX_PIN, LINK_TX_PIN);
  loadConfig();
  delay(300);
  Serial.println(F("\n[U2 controller] Team 13 Chocolate. Type help.\nFor a batch: BV-M OPEN, BV-J SHUT, then press START."));
  printConfig();
}

void loop() {
  pollLink();
  pollStart();
  doseStep();
  p4Step();
  batchStep();
  if (Serial.available()) handleCommand(Serial.readStringUntil('\n'));
}
